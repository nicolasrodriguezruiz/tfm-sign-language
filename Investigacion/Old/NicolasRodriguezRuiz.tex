\subsubsection{\underline{(2020): STMC}}
\textbf{Zhou et al., ``Spatial-Temporal Multi-Cue Network for Continuous Sign Language Recognition'' (AAAI 2020).}
En 2020, el estándar era combinar CNNs para extraer características visuales y RNNs (LSTMs/GRUs) para la secuencia temporal. Eran modelos pesados, difíciles de paralelizar y dependían fuertemente de que las ``glosas'' estuvieran perfectamente anotadas, lo cual es carísimo de conseguir.
\begin{itemize}
	\item \textbf{Datasets Utilizados.} El modelo se evalúa en tres benchmarks a gran escala:
	\begin {itemize}
		\item \textbf{PHOENIX-2014:} Dataset de lenguaje de señas alemán (dominio del clima).
		\item \textbf{CSL:} Dataset de lenguaje de señas chino (vida diaria).
		\item \textbf{PHOENIX-2014-T:} Versión extendida del primero, usado para traducción.
	\end{itemize}
	\item \textbf{Estructura del Modelo (STMC):} Tres módulos clave
	\begin{itemize}
		\item\textbf{Módulo Espacial Multi-Señal (SMC - Spatial Multi-Cue):} Procesar cada fotograma para descomponer características visuales específicas. Utiliza \href{https://docs.pytorch.org/vision/main/models/generated/torchvision.models.vgg11.html}{VGG-11} como red base.
		\begin{itemize}
			\item \textbf{Estimación de Postura:} rama autocontenida dentro de la red. Usa 2 capas \href{https://datasciencepythonblog.net/conv-transpose-tensorflow/}{deconvolucionales} y una capa Soft-Argmax para hacer la predicción de puntos clave (hombros, codos, muñecas, nariz) diferenciable.
			\item \textbf{Recorte de Parches:} Usa las coordenadas de la postura estimada para recortar regiones de interés: Cara y Ambas Manos.
			\item \textbf{Generación de Características:} Extrae vectores de características independientes para la \textbf{Imagen completa}, \textbf{Manos}, \textbf{Cara} y \textbf{Postura}.
		\end{itemize}
		\item \textbf{Módulo Temporal Multi-Señal:} Modela las correlaciones temporales a través de dos caminos paralelos (Intra e Inter).
		\begin{itemize}
			\item \textbf{Camino Intra-Cue (Intra-señal):} Modela la dependencia temporal interna de cada señal por separado (mantiene la unicidad de cada señal, ej. solo la mano).
			\item \textbf{Camino Inter-Cue (Inter-señal):} Fusiona la información de todas las señales para aprender la sinergia y colaboración entre ellas en diferentes escalas de tiempo.
			\item Utiliza convoluciones temporales (TCOV) y Pooling temporal
		\end{itemize}
		\item \textbf{Aprendizaje de Secuencia e Inferencia}
		\begin{itemize}
			\item \textbf{Codificador}: Usa \href{https://www.geeksforgeeks.org/nlp/bidirectional-lstm-in-nlp/}{BLSTM} (Bidirectional Long-Short Term Memory) para procesar las secuencias de características resultantes.
			\item \textbf{Alineación:} Utiliza \href{https://en.wikipedia.org/wiki/Connectionist_temporal_classification}{CTC} (Connectionist Temporal Classification) para alinear la secuencia de video con la secuencia de glosas (palabras).
		\end{itemize}
		\item \textbf{Estrategia de Optimización:} El entrenamiento es ``end-to-end'' utilizando una función de pérdida conjunta.
		\begin{itemize}
			\item Pérdida Principal, CTC sobre el camino Inter-Cue (la fusión).
			\item Pérdida Auxiliar: CTC sobre cada camino Intra-Cue (para forzar a la red a aprender buenas características individuales de manos/cara).
			\item Pérdida de Regresión: Smooth-L1 para la estimación de postura (supervisada por coordenadas ground-truth\footnote{Ground-Truth: Para cada imagen se conocen las coordenadas reales correctas}).
		\end{itemize}
		\item \textbf{Resultados:} Los experimentos demuestran que el STMC supera a los métodos anteriores.
		\begin{itemize}
			\item \textbf{PHOENIX-2014:} Logra un nuevo récord con una Tasa de Error de Palabra (WER) del $20.7\%$ en el set de prueba, superando al mejor competidor anterior (DNF\footnote{DNF se refiere a un método previo de vanguardia llamado ``\href{https://www.researchgate.net/publication/398875768_A_Deep_Neural_Framework_for_Continuous_Sign_Language_Recognition_via_Iterative_Training}{Deep Neural Framework}'', desarrollado por Cui, Liu y Zhang en 2019}) que tenía $22.9\%$.
			\item \textbf{CSL}: Supera al mejor competidor por un $4.1\%$ en WER
			\item \textbf{PHOENIX-2014-T:} Supera a todas las combinaciones del modelo CNN-LSTM-HMM.
		\end{itemize}
		\item Al integrar la estimación de postura dentro de la red (rama autocontenida), el modelo ahorra aproximadamente un $44\%$ del tiempo de inferencia en comparación con usar un estimador de postura externo
	\end{itemize}
\end{itemize}

\subsubsection{\underline{(2021-2022): Transformers}}
\textbf{Camgoz et al., ``Sign Language Transformers: Joint End-to-End Sign Language Recognition and Translation'' (CVPR 2020 / TPAMI 2021)}Aquí es donde los Vision Transformers (ViT) empiezan a reemplazar a las CNNs y las RNNs desaparecen. Propusieron usar un Transformer completo (Encoder-Decoder) para pasar de vídeo a texto. Introdujeron la idea de Joint Learning: entrenar a la vez el reconocimiento (vídeo $\to$ glosa) y la traducción (glosa $\to$ texto) en una sola red. 
\begin{itemize}
	\item \textbf{Dataset:} \textbf{RWTH-PHOENIX-Weather-2014T}, el estándar para traducción de lenguaje de señas.
	\item \textbf{Estructura del Modelo (Joint SLRT):} El modelo utiliza una arquitectura de Transformer con dos cabezales de salida,
	\begin{itemize}
		\item \textbf{Extracción de Características (Feature Extractor):} Usa una CNN (\href{https://github.com/LKLQQ/Inception-v2}{Inception-v2}) pre-entrenada para extraer vectores espaciales de cada fotograma del video.
		\item \textbf{Codificador del Transformer (Sign Encoder):} Aplica capas de atención (\href{https://www.ibm.com/es-es/think/topics/self-attention}{Self-Attention}) para modelar las relaciones temporales en el video.
		\item \textbf{Cabezal de Reconocimiento (Recognition):} Utiliza una pérdida CTC (Connectionist Temporal Classification) sobre la salida del codificador para predecir la secuencia de glosas.
		\item \textbf{Decodificador del Transformer (Translation):} Un decodificador de lenguaje natural que genera la traducción final palabra por palabra, atendiendo a las representaciones del codificador de señas.
		\item \textbf{Estrategia de Entrenamiento:} \emph{Aprendizaje Conjunto (Joint Learning)}, entrena el reconocimiento y la traducción al mismo tiempo. La pérdida de reconocimiento (CTC) actúa como un regulador que ayuda al modelo a aprender mejores representaciones visuales para la traducción.
	\end{itemize}
	\item \textbf{Resultados}
	\begin{itemize}
		\item Logra los mejores resultados hasta la fecha (2020) en traducción de lenguaje de señas.
		\item Supera significativamente a los modelos previos (basados en RNN/LSTM) en puntuaciones BLEU (calidad de traducción) y reduce el WER (tasa de error de palabra en reconocimiento).
		\item Aprender a reconocer glosas y traducir frases de forma conjunta es mucho más efectivo que intentar traducir directamente desde el video sin supervisión de glosas.
	\end{itemize}
	\item \textbf{Diferencia principal:} Es End2End. \textbf{Antes}, una red miraba el video y escribía una lista de palabras (glosas) y otra red distinta tomaba esas palabras escritas y las traducía a una frase. \textbf{Ahora}, aunque usa las glosas para aprender, el flujo de información es continuo; en lugar de generar texto de glosas y pasárselo al traductor, el modelo genera una representación vectorial rica. Las glosas sirven como un maestro o guía durante el entrenamiento para que la red no se pierda, pero la traducción final se hace basándose en la información completa del video, no solo en una lista de palabras detectadas.
\end{itemize}

\textbf{Min et al., ``Visual Alignment Constraint for Continuous Sign Language Recognition'' (ICCV 2021)}. Introducen la \href{https://github.com/VIPL-SLP/VAC_CSLR}{VAC} (Visual Alignment Constraint). Resuelve el problema de cómo sabe la red que el frame $45$ corresponde a la palabra "casa"? VAC fuerza al modelo a alinear mejor la atención visual con el texto sin necesidad de supervisión humana tan estricta.


\subsubsection{\underline{La Actualidad (2023-2024): Gloss-Free \& LLMs}}
La tendencia es eliminar la dependencia de las glosas (que son caras de anotar) y usar el conocimiento de los LLMs.
\subsubsection*{Gloss-Free SLT}
 \textbf{Zhou et al., "Gloss-Free Sign Language Translation: Improving from Visual-Language Pretraining" (ICCV 2023).} Proponen un modelo que no necesita glosas para entrenarse. Utilizan \href{https://openai.com/es-ES/index/clip/}{CLIP} (el modelo de OpenAI que une texto e imagen) para pre-entrenar el encoder visual. Al ''heredar'' el conocimiento de \emph{CLIP}, el modelo ya sabe relacionar conceptos visuales con texto, saltándose el paso intermedio de la glosa.
\begin{itemize}
	\item El enfoque propone una estrategia de dos etapas llamada \emph{Visual-Language Pretraining} (VLP) seguida de la traducción propiamente dicha.
	\begin{itemize}
		\item \textbf{Etapa 1: Pre-entrenamiento Visual-Lenguaje (VLP):} Esta etapa busca alinear las representaciones visuales (video) con las representaciones textuales (lenguaje) antes de intentar traducir.
		\begin{itemize}
			\item\textbf{ CLIP (Contrastive Language-Image Pretraining):} Alinea el video y el texto en un espacio semántico compartido. El codificador visual aprende a producir características que se parecen a las características del texto correspondiente.
			\item \textbf{Masked Self-Supervised Learning (Aprendizaje Auto-supervisado con Máscaras):} Entrena al decodificador de texto para reconstruir oraciones donde algunas palabras han sido ocultadas. Esto le enseña al modelo la estructura gramatical y semántica del lenguaje meta.
		\end{itemize}
		\item \textbf{Aumento de Datos:} Se aplican técnicas fuertes de aumento de datos (transformaciones geométricas, de color y temporales) a los videos para aumentar la diversidad y robustez del modelo.
	\end{itemize}
	\item \textbf{Etapa 2: Traducción de Lenguaje de Señas Libre de Glosas (GFSLT)} Se construye la arquitectura final de traducción heredando los pesos aprendidos en la Etapa 1.
	\begin{itemize}
		\item \textbf{Codificador Visual (Visual Encoder):} 
		\begin{itemize}
			\item Hereda los parámetros del codificador visual pre-entrenado en la Etapa 1.
			\item Procesa el video de señas para extraer características visuales ricas y orientadas al lenguaje.
		\end{itemize}
		\item \textbf{Decodificador de Texto (Text Decoder):}
		\begin{itemize}
			\item Hereda los parámetros del decodificador de texto pre-entrenado.	
			\item Genera la traducción palabra por palabra basándose directamente en las características visuales, sin pasar por glosas intermedias.	
		\end{itemize}
		\item \textbf{Entrenamiento End-to-End:} Todo el modelo se ajusta (fine-tuning) conjuntamente para la tarea de traducción
	\end{itemize}
\end{itemize}
\subsubsection*{Sign2GPT}
\textbf{Wong et al., "Sign2GPT: Leveraging Large Language Models for Gloss-Free Sign Language Translation" (ICLR 2024).} En lugar de entrenar un decoder desde cero, usan un LLM pre-entrenado (como GPT o LLaMA) como decoder. Usan adaptadores ligeros (Adapters/LoRA) para conectar el encoder de vídeo con el LLM. El texto generado es muchísimo más natural y fluido porque el modelo ``sabe escribir'' perfectamente gracias a su pre-entrenamiento masivo en texto. Demuestran que con suficientes datos y una arquitectura tipo Transformer pura, se puede superar a los modelos basados en glosas. Introducen técnicas de aumentación de datos y contrastive learning (aprender por comparación) para mejorar la precisión.

La meta sigue siendo eliminar la dependencia de las glosas y superar la escasez de datos en SLT transfiriendo conocimiento de modelos masivos entrenados en lenguaje hablado e imágenes generales. Se busca adaptar estos "gigantes" (como GPT y ViT) al dominio de señas mediante técnicas eficientes que no requieran re-entrenar todo el modelo.

\begin{itemize}
	\item \textbf{Datasets Utilizados}
		\begin{itemize}
			\item \textbf{RWTH-PHOENIX-Weather 2014T}: Dataset estándar de alemán (clima). \emph{Siempre es este...}
			\item \textbf{CSL-Daily:} Dataset de lenguaje de señas chino (vida diaria).
		\end{itemize}
	\item \textbf{Estructura}
	\begin{itemize}
		\item \textbf{Backbone Espacial (Visión):} 
		\begin{itemize}
			\item Usa \textbf{Dino-V2 (ViT-S/14)}, un Transformer de visión auto-supervisado.
			\item \textbf{Adaptación:} Se mantiene congelado (no se re-entrena todo) pero se le inyectan \href{https://www.ibm.com/think/topics/lora}{LoRA} (Low-Rank Adapters). Esto permite ajustar levemente el modelo para entender gestos sin gastar mucha memoria.
		\end{itemize}
		\item \textbf{Codificador de Señas (Sign Encoder):}
		\begin{itemize}
			\item Es la única parte que se entrena desde cero.
			\item Transforma las características visuales en una representación temporal comprimida.
			\item Usa atención local y \emph{downsampling temporal}\footnote{El downsampling temporal es una técnica para reducir la cantidad de frames de un video manteniendo lo más relevante en el tiempo. Es clave cuando trabajas con videos largos y quieres ahorrar cómputo, memoria o tiempo.} para manejar videos largos eficientemente.
		\end{itemize}
		\item \textbf{Decodificador de Lenguaje (LLM Decoder):}
		\begin{itemize}
			\item Usa \textbf{XGLM-1.7B}, un modelo tipo GPT multilingüe pre-entrenado masivo.
			\item \textbf{Adaptación:} Al igual que en la visión, el modelo principal se mantiene congelado. Se añaden capas de\emph{Zero-Gated Cross-Attention}\footnote{“Zero-Gated Cross-Attention” generalmente se refiere a un módulo de atención cruzada cuya influencia está controlada por una puerta inicializada (o restringida) a cero, por lo que el modelo comienza ignorando la señal cruzada y solo aprende a usarla si realmente es útil.} (atención cruzada con compuerta cero) para inyectar la información del video en el cerebro del LLM sin destruir su conocimiento lingüístico previo.
		\end{itemize}
	\end{itemize}
		\item \textbf{Estrategia de Pre-entrenamiento (Pseudo-Gloss Pretraining - PGP):} Para compensar la falta de glosas manuales, inventan un ``maestro automático''.
		\begin{itemize}
			\item \textbf{Generación de Pseudo-Glosas:} Usan herramientas de NLP (SpaCy) para extraer automáticamente palabras clave (sustantivos, verbos, adjetivos) de las oraciones traducidas. Estas pseudo-glosas siguen el orden del lenguaje hablado, no el de señas.
			\item \textbf{Entrenamiento con Prototipos:} Crean ``prototipos'' vectoriales para estas palabras usando embeddings (FastText). Entrenan al \emph{Codificador de Señas} para que sus representaciones visuales se parezcan a estos prototipos si la palabra aparece en la frase. Esto enseña al modelo a ``localizar'' conceptos visualmente antes de intentar traducir frases completas.
		\end{itemize}
	\item \textbf{Resultados} El modelo establece un nuevo estándar para la traducción sin glosas.
	\begin{itemize}
		\item \textbf{PHOENIX14T:} Mejora el BLEU-4 en $+1.1$ puntos respecto al mejor modelo anterior libre de glosas.
		\item\textbf{ CSL-Daily:} Mejora el BLEU-4 masivamente en $+4.4$ puntos.
		
		\item Demuestra que es posible usar modelos gigantes ($1.7$ Billones de parámetros) en tareas de video complejas usando adaptadores (LoRA), entrenando solo una fracción muy pequeña de los pesos totales. Logra resultados competitivos que se acercan cada vez más a los sistemas que sí usan supervisión costosa de glosas manuales, demostrando que la supervisión automática (pseudo-glosas) es una alternativa viable y escalable.
	\end{itemize}
		
\end{itemize}

\subsubsection{\underline{El Paradigma ``Gloss-based con LLM'' (2023-2025)}}
Este enfoque asume que el problema no es la glosa en sí, sino la incapacidad de los modelos antiguos (RNNs/LSTMs) para traducir esa glosa a un lenguaje natural fluido.

\begin{itemize}
	\item \textbf{ChatGPT como Traductor de Glosas (2024): }Un estudio reciente (\href{https://arxiv.org/abs/2403.10434v1}{``Using an LLM to Turn Sign Spottings into Spoken Language''}, \href{https://arxiv.org/abs/2403.10434}{Spotter+GPT: Turning Sign Spottings into Sentences with LLMs}) propone usar un detector de glosas simple y luego pasar esa lista sucia directamente a \emph{ChatGPT} (GPT-3.5).
	\item \textbf{Gloss2Text Específico (2024):} Otros investigadores han entrenado modelos específicos (fine-tuning) para esta tarea, superando a los métodos tradicionales. Utilizan técnicas como ``Label Smoothing'' semántico para manejar la ambigüedad de las glosas.
	\item \textbf{Pseudo-Glosas Generadas por LLMs:} Algunos trabajos (como el presentado en NeurIPS 2025) usan el LLM al revés durante el entrenamiento: le piden al LLM que genere ``pseudo-glosas'' a partir de texto normal para crear más datos de entrenamiento sintéticos, ya que anotar glosas reales es muy caro.
\end {itemize}

\href{https://personales.upv.es/thinkmind/dl/conferences/gptmb/gptmb_2025/gptmb_2025_1_30_30021.pdf}{\textbf{Assessing the Capabilities of Large Language Models in Translating ASL-GLOSS (2025):}}Prueban varios LLMs modernos con secuencias de glosas de ASL (Lengua de Señas Americana). Descubren que los modelos tienen una capacidad Zero-shot (sin ver ejemplos previos) sorprendentemente alta para entender la estructura "rota" de las glosas y generar inglés fluido, casi al nivel de traductores humanos expertos en ciertos contextos.


\subsubsection{\underline{Modelos basados en Keypoints (Pose-based SLT)}}
\textbf{El Argumento de la Privacidad}
\begin{itemize}
	\item \textbf{Anonimización Intrínseca:} Al extraer los esqueletos, eliminas la textura facial, el color de piel, la ropa y el fondo. Solo queda el movimiento.
	\item \textbf{Cumplimiento Normativo:} Facilita el cumplimiento del RGPD (GDPR). Una empresa podría procesar la traducción de un cliente sin ``ver'' realmente su cara, solo su geometría.
	\item \textbf{Sesgo:} Ayuda (aunque no elimina totalmente) a reducir el sesgo del modelo hacia ciertos tonos de piel o géneros, ya que el modelo se centra en la estructura ósea y no en la apariencia.
\end{itemize}

\subsubsection*{Entrada de datos (Input Representation)}
\begin{itemize}
	\item \textbf{Formato Crudo:} Un frame de vídeo $1920 \times 1080$ (millones de datos) se convierte en un vector simple. Normalmente se usan formatos tipo \emph{\href{https://github.com/CMU-Perceptual-Computing-Lab/openpose}{OpenPose}} o \emph{\href{https://github.com/google-ai-edge/mediapipe/blob/master/docs/solutions/holistic.md}{MediaPipe Holistic}}: \textbf{Cuerpo (Pose)}, 33 puntos $(x, y, z, visibility)$; \textbf{Manos (Hands)}, $21 \times 2$ puntos. \textbf{Cara (Face Mesh)}, $468$ puntos (a veces se reduce a un subconjunto de labios y cejas para ahorrar cómputo).
	\item \textbf{Pre-procesamiento (Normalización):} El modelo no aprenderá bien si usas las coordenadas de los píxeles originales (porque si la persona se acerca a la cámara, las coordenadas cambian). \textbf{Centrado:} restar la coordenada del ``cuello'' o ``nariz'' a todos los puntos (hacer que el cuello sea el origen $0,0$). \textbf{Escalado:} dividir por la distancia entre los hombros. Esto hace que el modelo entienda el signo igual, sea un niño o un adulto.
	\item \textbf{Ingeniería de Características (Feature Engineering):} Para ayudar al entrenamiento, muchos papers no solo meten la posición $(x,y)$, sino también, \textbf{velocidad:} $V_t = P_t - P_{t-1}$ (ayuda a capturar la dinámica del gesto); \textbf{ángulos óseos:} el ángulo entre el brazo y el antebrazo.
\end{itemize}
\subsubsection*{Eficiencia}
\begin{itemize}
	\item \textbf{Entrenamiento:} Un modelo de vídeo puede tardar semanas en entrenar en un cluster de GPUs. Un modelo de esqueletos puede entrenar en horas en una sola GPU decente.
	\item \textbf{Inferencia (Tiempo real):} Los modelos de keypoints son ligeros. El cuello de botella suele ser la extracción del esqueleto (\emph{MediaPipe}), no la traducción.
	\item \textbf{Trade-off (La desventaja):} Se pierde información sutil. Expresiones faciales complejas (como inflar los carrillos, fundamental en lengua de signos) a veces se pierden si el extractor de keypoints no es muy preciso.
\end{itemize}

\subsubsection*{Datasets?}
\textbf{How2Sign} tienen archivos \emph{.json} con \emph{OpenPose} ya extraídos para las $80h$ de vídeo. Es multimodal y enorme.

\subsubsection*{El intento más reciente y relevante (2025)}
\href{https://arxiv.org/abs/2507.01532v1}{\textbf{"Exploring Pose-based Sign Language Translation: Ablation Studies and Attention Insights" (Zelezny et al., 2025 - arXiv).}} Se centraron exclusivamente en usar esqueletos (pose-based) en How2Sign. Demostraron que la normalización de los keypoints es crítica.

\subsubsection{Resumen?}
Mientras que en 2020 el estado del arte (STMC) dependía de arquitecturas híbridas y una fuerte supervisión mediante glosas, la literatura reciente (2023-2024) muestra un cambio de paradigma hacia enfoques Gloss-Free. Estos nuevos modelos aprovechan el Pre-entrenamiento Visión-Lenguaje (VLP) y la capacidad generativa de los LLMs (como en Sign2GPT) para realizar traducciones directas de vídeo a texto, superando las limitaciones de escasez de datos anotados que históricamente han frenado el avance del campo.
